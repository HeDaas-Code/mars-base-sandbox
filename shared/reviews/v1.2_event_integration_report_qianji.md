## 一、改动清单

### 1. `shared/mars-base/frontend/ws/client.js`

**新增方法：`sendOptionSelect(eventId, optionId, followupId?)`**

- 用途：发送 v1.2 §11.4 `option_select` C→S 消息
- 参数：
  - `eventId` — 当前事件 ID（从 `eventPanel.activeEvent.event_id` 取）
  - `optionId` — 玩家所选选项 ID
  - `followupId` — 父选项 ID（仅二级选项回传时传入，对应 v1.2 §11.4 `followup_id` 字段）
- mock 模式下走 `_mockHandleOptionSelect`，模拟后端 event_scheduler 响应

**新增方法：`_mockHandleOptionSelect(eventId, optionId, followupId)`**

- 用途：前端独立联调时模拟后端 option_result 推送
- 路由逻辑：
  - 二级选项回传（`followupId` 非空）→ 推 `option_result`（`leads_to` 非空，`followup=null`）
  - 一级选项带 followup → 推 `option_result`（`followup` 字段非空，触发二级面板）
  - 普通一级选项 → 推 `option_result`（`effects_summary` / `state_update` / `leads_to` 非空）
- 数据源：引用 `event-panel.js` 全局的 `MOCK_V12_STORY_EVENT`

### 2. `shared/mars-base/frontend/terminal/app.js`

**改动点 A：`onOptionSelect` / `onFollowupSelect` 回调改走 `sendOptionSelect`**

- 旧实现：临时走 `player_input` 通道（`marsClient.sendPlayerInput('[opt]'+optionId)`）
- 新实现：调用 `marsClient.sendOptionSelect(eventId, optionId)` / `marsClient.sendOptionSelect(eventId, followupOptionId, parentOptionId)`
- 事件 ID 来源：`eventPanel.activeEvent?.event_id`
- 父选项 ID 来源：`eventPanel.selectedOption`（v1.2 §11.4 `followup_id` 字段）

**改动点 B：`option_result` 路由补全**

- 旧实现：仅处理 `followup` 字段，注释标注 "effects_summary / state_update 等其他字段的渲染等云逸 v1.2 §11 schema 定稿后再接入"
- 新实现（v1.2 §11.6 路由逻辑）：
  - `followup` 字段非空 → 调用 `eventPanel.renderFollowup(p.followup, eventStreamEl)`（Case 1 B 二级选项面板）
  - 否则 → 调用 `eventPanel.renderOptionResult(p, eventStreamEl, optionLabel)`（渲染 effects_summary + state_update + leads_to 反馈条）
- `optionLabel` 从 `eventPanel.activeEvent.options` 反查 `option_id` 对应的 `label`

**改动点 C：Mock 触发器切到 v1.2 数据**

- `triggerMockEvent`：`MOCK_EVENT_DATA` → `MOCK_V12_STORY_EVENT`
- 新增 `triggerMockOptionResult`：调用 `eventPanel.renderOptionResult(MOCK_V12_OPTION_RESULT, ...)`
- `triggerMockFollowup`：从 `MOCK_V12_STORY_EVENT.options` 取带 `followup` 的选项的 `followup` 字段做演示
- `shell.onMockCommand` 路由扩展：`event` / `result` / `followup` 三种 mock 命令
