## 二、视觉侧缺口（对应千机盘点）

### 缺口1：事件呈现 UI ★★★ 核心阻塞

**需求来源**：千机第2项「前端缺事件呈现UI」+ 第3项「多轮任务循环」

当后端事件调度器触发剧情节点时，前端需要一套完整的视觉呈现方案：

| 子项 | 说明 | 优先级 | 预估工时 |
|------|------|--------|---------|
| 事件弹窗面板 | 剧情事件触发时的弹窗/面板样式（系统消息风格，带信号干扰效果） | P0 | 2h |
| 玩家选项渲染 | `player_options` 的视觉呈现（可选项列表 + 选中高亮 + 信号遮罩） | P0 | 2h |
| 任务下达面板 | NPC下达任务的视觉模板（任务标题/描述/目标/奖励） | P0 | 2h |
| 任务追踪条 | 当前进行中任务的精简显示（底部或侧栏，类似任务日志） | P1 | 1.5h |
| 事件结果反馈 | 选项执行后的结果展示（effects 可视化：资源变化/状态变化/解锁内容） | P0 | 2h |
| Sol 推进显示 | Sol 时钟推进的视觉动画（数字翻转 + 章节切换过渡） | P1 | 1h |
| 分支选择提示器 | 玩家面临分支选择时的视觉引导（闪烁箭头/高亮提示） | P1 | 1h |

**设计方向**：事件UI应与终端风格统一——不使用弹窗浮层（破坏沉浸感），而是通过终端内消息流呈现，配合信号遮罩和NPC标识符区分事件类型。

### 缺口2：探索视图视觉内容 ★★ 次要

**需求来源**：千机次要差距「Shell命令扩展 cd/cat/man/scan」

### 5.2 四个核心子组件

1. **事件弹窗面板** `render()` — 嵌入终端流（非浮层），含类型色条/头部标签/Sol/分支/节点号
2. **玩家选项渲染** `renderOptions()` — 键盘1/2/3快捷选择 + 风险提示 + 推荐标记 + 分支锁定提示
3. **任务下达面板** `renderTaskBriefing()` — NPC发起/目标列表/奖励展示
4. **事件结果反馈** `renderResult()` — effects字段逐行渲染（state_set/trust_delta/morale_delta/branch_progress/risk）

### 5.3 字段映射（YAML → UI）

| YAML 字段 | UI 渲染位置 | 说明 |
|-----------|-------------|------|
| event_id | data-option-id | 内部标识 |
| node_index | 头部"节点N" | 节点序号 |
| description | 事件描述区 | 走信号遮罩，NPC名高亮 |
| bound_npcs | 绑定NPC标记条 | primary高亮，其余常态 |
| player_options[].label | 选项按钮 | 点击/键盘选择 |
| player_options[].risk | 选项风险行 | ⚠ 图标 + 红色斜体 |
| effects.state_set | 结果反馈：⚙ 行 | 数值正绿负红 |
| effects.trust_delta | 结果反馈：◈ 行 | NPC符号+名+信任变化 |
| effects.morale_delta | 结果反馈：♥ 行 | 士气变化 |
| effects.branch_progress | 结果反馈：▸ 行 | 分支进度点（5格） |
| effects.risk | 结果反馈：⚠ 行 | 风险提示文字 |
| ending_determination | 结局面板 | 紫色发光边框 + 居中 |

### 5.4 信号遮罩适配

事件描述走 SignalRenderer 四档遮罩（L1-L4），与NPC对话消息一致。
- L2(50-79%): 描述 opacity 0.85
- L3(20-49%): 描述 opacity 0.6，选项 opacity 0.85
- L4(0-19%): 描述 opacity 0.35，选项 opacity 0.7，禁用抖动动画
- NPC名引用段标记为 protected=true，不被遮罩

### 5.5 等待项

**WebSocket消息Schema**（锐锋/云逸待定义）：
- `event_trigger` 消息：需含 event_id, node_index, branch, event_type, sol, description, bound_npcs, player_options
- `option_submit_response` 消息：需含 selected_option_id, effects (state_set/trust_delta/morale_delta/branch_progress/risk)
- `sol_advance` 消息：需含 sol, delta, chapter

Schema 定稿后，只需将 `render(data)` 的 data 源从 MOCK_EVENT_DATA 切换为 WebSocket 消息体，视觉层结构不变。

## 七、与千机的协作约定

1. **集成方式**：千机在主终端流中调用 `eventPanel.render(data, targetEl)` 即可挂载事件面板
2. **选项回调**：注册 `eventPanel.onOptionSelect = (optionId) => { ws.send(...) }` 将选择发回后端
3. **结果渲染**：收到后端 effects 后调用 `eventPanel.renderResult(effects, targetEl, optionLabel)`
4. **联调测试**：事件UI需在后端事件调度器就绪后做一轮端到端验证
